# Admiral Post — подключение админ-панели к Supabase

Код и SQL находятся в репозитории, но интеграция не заработает, пока не создан и не настроен проект Supabase. Секретные ключи в GitHub не добавлять.

## 1. Создать проект
1. Создайте проект в Supabase Dashboard и сохраните пароль базы в своём менеджере паролей.
2. В SQL Editor выполните целиком файл `supabase/migrations/202610230001_admin_panel.sql`.
3. В Authentication → Users создайте пользователя администратора с вашим рабочим email.
4. В Authentication → Users откройте пользователя и задайте в **app_metadata** значение `{"is_admin": true}`. Не используйте user_metadata для этой роли — пользователь может менять user_metadata самостоятельно. Если интерфейс не позволяет редактировать app_metadata, выполните это через доверенный серверный Admin API или попросите владельца проекта настроить роль. Никогда не публикуйте service role/secret key.

## 2. Подключить сайт
1. В Project Settings → API скопируйте Project URL и **publishable key** (старый anon key тоже публичный, если RLS настроен).
2. В файле `supabase-config.js` замените пустые `url` и `publishableKey` на эти значения. Это публичная конфигурация, секретный ключ сюда не вставлять.
3. В `supabase/config.toml` замените `REPLACE_WITH_YOUR_SUPABASE_PROJECT_REF` на project ref из URL проекта.

## 3. Развернуть публичную функцию приёма заявок
Установите Supabase CLI, войдите в аккаунт и из корня репозитория выполните:
```sh
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase secrets set SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
supabase functions deploy submit-quote
```
Используйте секретный/ service_role key только в локальной команде терминала или Secret Manager; не присылайте его в чат, не сохраняйте в репозитории и не добавляйте в скриншоты. На некоторых проектах ключ автоматически доступен Edge Functions; если он доступен как `SUPABASE_SECRET_KEY`, отдельный секрет не требуется.

## 4. Проверка
- Откройте `https://www.admiral-post.com/admin.html`; должна появиться форма входа, а не сообщение о пустой конфигурации.
- Войдите администратором.
- Отправьте тестовую заявку с сайта и проверьте, что она появляется в «Заявки с сайта».
- Создайте тестовое отправление и измените его статус.
- Проверьте, что без входа запросы к таблицам `quote_requests` и `shipments` запрещены.
- После проверки удалите тестовые записи.

## Что сейчас реализовано
- Таблицы заявок и отправлений, статусы, внутренние заметки, RLS-политики только для пользователей с `app_metadata.is_admin=true`.
- Edge Function принимает и валидирует заявки с сайта; в коде есть ограничение размера запроса, honeypot и best-effort rate limit.
- Админка: вход, список/поиск/фильтры заявок, обновление статуса и заметок, регистрация отправления, изменение статусов и сводные счётчики.

## Ограничения первого этапа
- Публичная функция не отправляет email/SMS-уведомления.
- Реестр отправлений не подключён к реальной транспортной системе и не создаёт почтовые этикетки.
- Публичный трекинг на главной остаётся заглушкой — его нужно отдельно связать с реальными данными и определить, какие статусы безопасно показывать по номеру.
- Rate limit в этой первой версии best-effort, не полноценная защита от распределённых атак. Перед масштабированием добавьте CAPTCHA/Turnstile, централизованный rate limit и мониторинг.
