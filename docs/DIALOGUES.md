# Диалоги Admiral Post

Откройте admin.html → Диалоги. Используется существующий вход администратора.

Входящие — незакрытые обращения без ответственного; Мои — назначенные текущему администратору; Все — все обращения. Поиск имени, телефона, email и темы выполняется на сервере, страницы по 50 строк. История загружается по 100 сообщений, более ранние доступны кнопкой. Нажатие на имя открывает карточку.

Ручной диалог позволяет записать сообщение клиента, ответ оператора или внутреннюю заметку. Это запись истории, не отправка сообщения клиенту. Публичный чат, генерация ИИ-ответов и доставка сообщений в этой версии не подключены. Резюме редактируется вручную, не выдаётся за автоматически созданное ИИ.

Создание заявки требует имени, телефона, email, страны, веса, подтверждения данных и согласия клиента. RPC convert_conversation блокирует строку диалога и атомарно создаёт запись quote_requests, сохраняет связь и заметку. Повторный вызов возвращает существующую заявку. Создание заявки не назначает курьера.

## Контракт подключения консультанта

Доверенный сервер будущего консультанта создаёт conversations с channel=website_ai или website_operator. Сервер пишет conversation_messages с role=customer/assistant/operator; external_id должен быть стабильным идентификатором сообщения для исключения повторов. Никогда не передавать service_role в браузер. Публичный доступ к этим таблицам отсутствует. До подключения публичного чата сервер должен проверять принадлежность сессии посетителю, согласие, лимиты запросов и длину сообщений; внутренние note/system, draft и персональные данные других диалогов посетителю не возвращать.

ИИ заполняет draft как предложение; оператор проверяет его и подтверждает создание заявки. ИИ не должен самостоятельно устанавливать согласие клиента. Для автоматического создания заявок ИИ потребуется отдельный серверный путь подтверждения; текущий RPC доступен только администраторам.

## Проверка

node --check admin-dialogues.js
SQL-проверки прав, преобразования и повторного вызова — tests/dialogues.sql. Запускать целиком: тестовые записи откатываются через ROLLBACK. Требуется хотя бы один существующий администратор. Проверка не отправляет уведомления клиентам.
